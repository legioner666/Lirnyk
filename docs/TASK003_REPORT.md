# TASK 003 — приватний прототип Spotify App Remote (`claude/spotify`)

Окремий застосунок **Lirnyk Remote** (`app.lirnyk.remote`, «Лірник Дистанційне»). Він встановлюється поруч з основним Lirnyk (`app.lirnyk`): інший applicationId, спільних компонентів і authority немає. В основний продукт не інтегрований.

## Конфігурація

| | |
|---|---|
| Spotify Client ID | `c3f21482d91c430d95342f864e41e6ef` (публічний; Client Secret не використовується і ніде не зберігається) |

| SDK | Spotify App Remote 0.8.0, офіційний репозиторій `spotify/android-sdk` (Apache-2.0). Завантажується в CI скриптом `scripts/fetch-spotify-sdk.sh` з закріпленого коміту з перевіркою SHA-256. Бінарний файл у репозиторій не комітиться |

## Що реалізовано

1. **Офіційна авторизація.** Використовується вбудований механізм App Remote: `ConnectionParams.showAuthView(true)` (README `spotify/android-sdk`, спосіб 2).
   - Spotify показує свій екран згоди на `app-remote-control`.
   - Токен у застосунок не потрапляє, тому зберігати секрети немає потреби.
   - Окрема бібліотека авторизації не потрібна. Через це в застосунку **немає дозволу INTERNET**: зв'язок іде з Spotify на пристрої, мережею займається сам Spotify.
2. **App Remote і реактивний стан.** `RemoteController` (чистий Kotlin, протестований) з `StateFlow` статусу і стану плеєра.
   - Одне з'єднання за раз. Пізні відповіді від покинутих спроб ігноруються.
   - Після обриву перепідключається сам з паузами 2/5/15/30/60 с — лише якщо застосунок уже авторизовано. Екран згоди без натискання користувача не відкривається ніколи.
3. **Керування і дані.**
   - Кнопки: грати/пауза, далі, назад, перемотування, перемішування, повтор (вимк./контекст/трек).
   - Обмеження Spotify (`PlayerRestrictions`) вимикають відповідні кнопки, жодна заборонена команда не надсилається.
   - Показуються назва, виконавець, альбом.
   - Обкладинка надходить через `ImagesApi`: її передає Spotify, а не мережа. У пам'яті тримаються 4 останні.
   - Прогрес рухається локально між оновленнями Spotify, Spotify не опитується.
4. **Відключення, видалення даних, повторна авторизація.**
   - «Відключити» — з'єднання закривається, авторизація лишається.
   - «Відключити і видалити дані» — з'єднання закривається, видаляються позначка авторизації і кеш обкладинок. Після цього потрібна повна повторна авторизація.
   - «Відкликати доступ в акаунті Spotify» відкриває `spotify.com/account/apps`: саму авторизацію відкликає лише Spotify.
   - Якщо доступ відкликано, наступне підключення повертає `UserNotAuthorizedException`. Застосунок показує кнопку «Авторизувати в Spotify».
5. **Діагностика помилок.** Кожен виняток SDK має зрозумілий текст українською, англійською і польською. Зокрема `AuthenticationFailedException` — це невідповідність пакета, SHA-1 чи Redirect URI.
6. **Підпис і SHA-1 (п. 9).**
   - CI підписує APK лише постійним тестовим ключем власника.
   - Сертифікат APK звіряється з `LIRNYK_TEST_CERT_SHA1`; якщо значення не збігається, збірка зупиняється.
   - Застосунок під час роботи показує свій SHA-1 і пише, чи збігається він із зареєстрованим.

## Приватний канал APK (п. 7–8)

- `scripts/termux/setup-signing.sh` — власник запускає один раз у Termux. Скрипт:
  - створює ключ і паролі на телефоні;
  - кладе їх у секрети GitHub через `gh`;
  - друкує SHA-1 для Spotify.

  Через чат нічого не передається.
- `.github/workflows/spotify.yml`:
  - збирає APK;
  - перевіряє маніфест (без мережі, слухача сповіщень, accessibility) і SHA-1;
  - **шифрує** APK (AES-256-CBC, PBKDF2, 200 000 ітерацій) паролем власника;
  - завантажує його як artifact на 14 днів.

  GitHub Releases не використовується.
- `scripts/termux/get-remote-apk.sh`:
  - бере останню успішну збірку;
  - розшифровує її на телефоні;
  - звіряє SHA-256;
  - відкриває встановлення.

## Тести

`spotify:model` — 13 JVM-тестів:
- перше підключення з екраном згоди;
- тихе повторне підключення;
- відкликана авторизація без повторних спроб;
- неправильний SHA-1 без повторних спроб;
- повтори з паузами і їх зупинка при відключенні;
- пізня відповідь покинутої спроби;
- видалення даних;
- команди з урахуванням обмежень;
- Spotify не встановлено;
- прогрес, цикл повтору, класифікація помилок, порівняння відбитків.

Lint без помилок. Release APK 2,0 МБ. У маніфесті лише приватний дозвіл androidx.

## Не перевірено фізично

Застосунок ще не запускався на пристрої. Невідомо:
- чи Spotify прийме цей застосунок (це залежить від пакета і SHA-1 у Dashboard та від Premium-акаунта власника в списку користувачів режиму розробки);
- як App Remote поводиться на магнітолі (Spotify має бути встановлений і онлайн).

## Правила Spotify — до будь-якої інтеграції в основний продукт

Прототип — особиста розробка в режимі Development Mode. Перед перенесенням в основний Lirnyk потрібно письмове підтвердження допустимості за правилами Spotify:
- Developer Terms;
- Developer Policy: автомобільне використання, назва і бренд, поширення поза Google Play, вимога Premium;
- квоти Development / Extended Quota Mode.

Питання сформульовано для власника. Звернутися можна через Spotify for Developers (форум або підтримку). Доти Spotify-код лишається лише в гілці `claude/spotify`.
